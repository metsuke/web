MOM (MetsuOS Methodology) 🔴②

El Proyecto | Implementacion de MOM

Capa: Sistema de Especificación y Metodología de Desarrollo
Propósito: Garantizar el control férreo, trazabilidad y contención de IA mediante especificación atómica bajo la norma ESA PSS-05.
Herramientas Core: Python 3.11+, Poetry, Pydantic, JSON atómicos, Jinja2 CLI.

1. Filosofía MOM: Desarrollo A Prueba de IA

La inteligencia artificial falla en proyectos de software cuando dispone de demasiada libertad de código y escaso contexto de las reglas/límites.

MOM resuelve esto aplicando la metodología ESA (European Space Agency Software Engineering Standards) llevada a la atomización extrema:

  • Ningún código o componente se escribe sin una trazabilidad previa e inmutable.
  • Cada requerimiento o arquitectura está troceado en unidades mínimas independientes (ficheros JSON atómicos).
  • La IA no "decide" la estructura global: solo ejecuta o refactoriza dentro de los límites estrictos marcados por los esquemas JSON.

2. Flujo de Trazabilidad ESA (PSS-05)

MOM implementa una cascada estricta de documentos spec mediante el patrón de parentesco id / parent_ids / child_ids:

flowchart TD
    URD["URD - User Requirements Document"] --> SRD["SRD - Software Requirements Document"]
    SRD --> ADD["ADD - Architectural Design Document"]
    ADD --> DDD["DDD - Detailed Design Document"]

Reglas de Trazabilidad

  • Todo elemento SRD debe apuntar como mínimo a un URD padre.
  • Todo elemento ADD define componentes de arquitectura trazados hacia un SRD.
  • Todo elemento DDD define funciones/clases específicas trazadas hacia un ADD.
  • Si la IA sugiere un cambio en el código (DDD), MOM verifica automáticamente que no rompa el contrato de los padres (ADD, SRD, URD).

3. Estructura de Proyecto, Persistencia Atómica y Entregables

MOM organiza las especificaciones en doc/src/ mediante un archivo JSON por cada ítem. El compilador de MOM genera dos formas complementarias de navegación:

  1. Documentación Consolidada (doc/*.md): Lectura lineal y formal por fases ESA.
  2. Vault Navegable (vault/): Estructura hipervinculada interactiva para Obsidian.

4. Esquema Atómico Estándar (JSON)

Cualquier especificación en MOM sigue la siguiente estructura validada por Pydantic:

{
  "id": "SRD-001",
  "phase": "srd",
  "title": "Mecanismo de Tres Colas por Comando en MIS",
  "description": "Todo comando invocado en MIS debe depositarse en una cola RT, Normal o Low, bloqueando la ejecución del script invocador hasta que un daemon devuelva el control.",
  "parent_ids": ["URD-001"],
  "child_ids": ["ADD-SCHEDULER"],
  "attributes": {
    "priority": "CRITICAL",
    "verification_method": "UNIT_TEST",
    "status": "APPROVED"
  },
  "metadata": {
    "author": "Metsuke",
    "ai_guardrails": "Prohibido ejecutar subprocesos directos del SO anfitrión fuera del gestor de colas."
  }
}

5. El Compilador MOM y Generación de Entregables

El motor compilador en Python realiza dos tareas fundamentales:

  1. Compilación Lineal (doc/*.md): Lee todos los JSONs de cada fase en doc/src/{fase}/, verifica su integridad y compila un documento único por fase directamente en la raíz de /doc.
  2. Generación del Vault (vault/): Crea una nota individual .md por cada ítem JSON dentro de la carpeta vault/, convirtiendo las relaciones parent_ids y child_ids en enlaces nativos tipo Wikilink (<a class='internal' href='../publicbrain/id.html'>ID</a>) y añadiendo metadatos Frontmatter en YAML para visualización y análisis de grafo en Obsidian.
