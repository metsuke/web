1. Visión General de la Arquitectura MPL

El lenguaje MPL (Metsu Programming Language) se concibe como un lenguaje de programación y especificación estructurado en capas jerárquicas de abstracción. Su objetivo principal es cerrar la brecha entre la definición en lenguaje humano de alto nivel (requisitos y flujos de usuario) y la ejecución lógica formal en código computable.

MPL se estructura en tres capas principales de pseudocódigo, sobre las cuales se sitúa una capa superior de definición funcional (URD):

2. Descripción Detallada de Capas

2.1. Capa URD (User Requirements Definition)

  • Naturaleza: Capa de definición narrativa e intuitiva escrita strictly en castellano (es-ES).
  • Propósito: Definir el comportamiento global del sistema, pantallas, transiciones, casos de uso y experiencias de usuario de forma legible para personal no técnico.
  • Mapeo: Sirve como la especificación origen que el compilador/transpilador de MPL analiza para derivar las capas de pseudocódigo formal.

2.2. Capa 3: Pseudocódigo de Alto Nivel (Human-Centric DSL)

  • Naturaleza: Pseudocódigo estructurado pero expresado mediante léxico y gramática formalizada en es-ES.
  • Sintaxis: Utiliza palabras clave en español (PANTALLA, CUANDO_PULSAR, TRANSICIONAR_A, MENÚ_OPCIONES).
  • Función: Define la topología de la aplicación, vistas, estados de interfaz y flujos directos de navegación.

2.3. Capa 2: Objetos Conceptuales e Interacciones

  • Naturaleza: Orientada a entidades relacionales, modelos de datos y buses de eventos.
  • Componentes:
  • Objetos de Datos (DataHolders): Almacenan el estado local o persistente (p. ej., documentos PDF, vectores, prompts, estados de la IA).
  • Interacciones: Definición de eventos, emisores, receptores y canalización de señales.

2.4. Capa 1: Pseudocódigo Formal Estándar

  • Naturaleza: Código imperativo/estructurado clásico de bajo nivel conceptual.
  • Componentes: Control de flujo (SI, MIENTRAS, PARA), tipos de datos primitivos (entero, cadena, booleano, arreglo), invocación de métodos del sistema base.

3.1. Extracción de Módulos del Sistema (mom-py)

  1. Agente de Ingesta y Extracción (pdf_extractor_ultra.py, pdf_parser.py, ingest_agent.py)
  2. Funcionalidad: Extracción intensiva de texto y estructura desde documentos PDF, procesamiento OCR, normalización de documentos.

  3. Mapeo en MPL (Capa 2): Objeto conceptual ExtractorDocumental y DocumentoPDF.

  4. Gestión de Clusters e IA (ai_cluster_manager.py, ingest_agent_ai.py, agent.py)

  5. Funcionalidad: Agrupamiento de contexto, procesamiento mediante modelos de lenguaje, orquestación de embeddings y clusters de conocimiento.

  6. Mapeo en MPL (Capa 2): Objeto conceptual ClusterConocimiento y AgenteIA.

  7. Esquemas y Persistencia (schemas.py, crud.py, projects.py, migrate.py)

  8. Funcionalidad: Gestión de esquemas de datos, operaciones CRUD, migración de base de datos y gestión de proyectos.

  9. Mapeo en MPL (Capa 2): Objeto conceptual RepositorioProyecto y GestorEstructuras.

  10. Interfaz de Línea de Comandos (cli.py, compiler.py)

  11. Funcionalidad: Punto de entrada para ejecución de comandos, compilación de tareas y pipeline de transformación.
  12. Mapeo en MPL (Capa 1/2): Módulo nativo SistemaCLI y PipelineCompilador.

4. Ejemplo de Mapeo Multi-Capa en MPL

A continuación se ilustra cómo se define un flujo de la aplicación en las diferentes capas de MPL:

4.1. Definición en Capa URD (Español es-ES)

La aplicación muestra una pantalla de carga mientras inicializa los agentes de ingesta de documentos. Al pulsar cualquier tecla, el usuario pasa a la pantalla del menú principal con 3 opciones: 'Procesar PDF', 'Consultar Cluster IA' y 'Salir'.

4.2. Definición en Capa 3 (Pseudocódigo de Alto Nivel es-ES)

PANTALLA PantallaCarga:
    MOSTRAR "Inicializando componentes de mom-py..."
    AL_PULSAR_TECLA:
        TRANSICIONAR_A PantallaMenuPrincipal

PANTALLA PantallaMenuPrincipal:
    TITULO "Menú Principal - MPL Manager"
    OPCION "1. Procesar PDF" CON_ACCION IniciarIngestaPDF
    OPCION "2. Consultar Cluster IA" CON_ACCION IniciarConsultaIA
    OPCION "3. Salir" CON_ACCION FinalizarAplicacion

4.3. Definición en Capa 2 (Objetos Conceptuales e Interacciones)

OBJETO_CONCEPTUAL GestorMenu:
    DATOS:
        estado_interfaz: Cadena
        lista_opciones: Lista[Cadena]
    INTERACCIONES:
        METODO inicializar_agentes():
            llamar IngestAgent.conectar()
            llamar AIClusterManager.sincronizar()
        METODO capturar_evento_tecla(tecla: EventoTecla):
            SI estado_interfaz == "CARGA":
                CAMBIAR_ESTADO("MENU_PRINCIPAL")

OBJETO_CONCEPTUAL DocumentoProcesable:
    DATOS:
        ruta_archivo: Cadena
        metadatos: Diccionario
        contenido_extraido: Cadena
    INTERACCIONES:
        METODO ejecutar_ocr():
            llamar OCREngine.procesar(ruta_archivo)

4.4. Definición en Capa 1 (Pseudocódigo Formal Imperativo)

FUNCION IniciarIngestaPDF(ruta: cadena) -> booleano:
    VARIABLE doc: DocumentoProcesable
    doc.ruta_archivo = ruta

    SI NO Archivo.existe(ruta) ENTONCES:
        Imprimir("Error: El archivo no existe.")
        RETORNAR Falso
    FIN_SI

    VARIABLE resultado_ocr: cadena
    resultado_ocr = OCREngine_ProcesarPaginas(doc.ruta_archivo)

    SI Longitud(resultado_ocr) > 0 ENTONCES:
        doc.contenido_extraido = resultado_ocr
        CRUD_GuardarDocumento(doc)
        RETORNAR Verdadero
    SINO:
        RETORNAR Falso
    FIN_SI
FIN_FUNCION
