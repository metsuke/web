MIS (MetsuOS Implementation System) ⚫①

El Proyecto

Capa: Sistema de Implementación / Entorno OS Emulado
Propósito: Definir el sistema operativo genérico compatible con Linux y el conjunto de normas mecánicas de implementación a prueba de fallos de IA.
Base Tecnológica: Python 3.11+ con entorno gestionado mediante Poetry.

1. Visión General

MIS no es una distribución comercial ni un sistema operativo tradicional instalado sobre metal o hipervisor tipo QEMU/KVM; es un entorno emulado en Python que abstrae la máquina anfitriona (Host OS) como si fuera hardware físico (Host-as-Hardware).

Proporciona la base sobre la cual se implementan las futuras distribuciones (siendo MOS2 la primera distro construida sobre MIS).

2. Arquitectura de Ejecución Asíncrona: Sistema Tri-Cola y Daemons

La característica interna más crítica y distintiva de MIS es que ningún comando o binario se ejecuta directamente de forma síncrona o bloqueante sobre el SO anfitrión.

2.1 El Mecanismo de Tres Colas por Comando

Cada comando o proceso en MIS tiene asociadas tres colas prioritarias:

  1. RT (Real-Time Queue): Tareas críticas e ininterrumpibles (ej. I/O de periféricos, refresco de pantalla X11, señales de interrupción de kernel).
  2. Normal Queue: Ejecución de comandos de usuario, scripts convencionales y tareas de procesamiento estándar.
  3. Low Queue: Tareas de fondo, indexación, recolección de basura, optimización o tareas diferidas.

2.2 Flujo de Control y Reanudación de Scripts

  1. Cuando un script o proceso invoca un comando en MIS, la instrucción es despachada a una de las tres colas.
  2. El script emisor entra en un estado pausado/suspendido (liberando CPU).
  3. El Daemon de Planificación Inteligente procesa las colas evaluando la prioridad y el estado del hardware/entorno.
  4. Una vez finalizada la ejecución del comando encolado, el Daemon devuelve el estado de salida (exit code) y datos al script emisor.
  5. El script emisor reanuda su ejecución y lanza la siguiente instrucción.

3. Gobernanza Térmica, Consumo de Recursos y P2P

Este modelo asíncrono encolado permite un control adaptativo y dinámico que los sistemas operativos tradicionales no ofrecen de forma nativa:

  • Control Térmico y Energético: El Scheduler ajusta el ancho de banda de procesamiento (throttling) y el consumo en función de la temperatura ambiente/CPU reportada por sensores del sistema anfitrión.
  • Ajuste de Potencia Dinámico: En condiciones de alta temperatura o baja batería, el Scheduler congela temporalmente la cola Low y desacelera la cola Normal, dando paso exclusivo a la cola RT.
  • Red P2P de Ejecución: Permite que las tareas de la cola Low o Normal puedan ser delegadas de forma transparente a otros nodos MIS dentro de una red local o P2P sin romper el flujo del script local.

4. Componentes Base de MIS

  1. MIS Kernel (PyKernel): Emulación de syscalls POSIX, tabla de procesos virtuales y memoria aislada usando estructuras nativas de Python.
  2. MIS Drivers: Envoltorios (wrappers) sobre librerías Python (Pillow, cffi, PyAudio, etc.) interpretados internamente como controladores de dispositivos de hardware.
  3. MIS Display / X Server: Servidor gráfico virtual que expone un framebuffer/canvas donde la GUI de la distro genera sus ventanas.
  4. MIS Shell: Intérprete de comandos compatible con sintaxis POSIX básica que conversa exclusivamente con el gestor de colas de MIS.
